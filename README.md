# Conversational AI Chatbot: From Scratch Transformer to LoRA Fine-Tuning

An end-to-end conversational AI project exploring different approaches to building a chatbot, starting with a Transformer architecture implemented from scratch and progressing to transfer learning with Qwen2.5-1.5B-Instruct and LoRA fine-tuning on the DailyDialog dataset.

The project focuses on understanding the development process, comparing different modeling approaches, evaluating their limitations, and deploying a conversational interface using Gradio.

## Project Overview

Building a conversational chatbot from scratch is challenging. A Transformer architecture may be implemented correctly and trained on conversational data, yet still produce responses that are less natural, coherent, or contextually relevant than those generated by a pretrained language model.

Rather than stopping at the initial implementation, I explored a progression of approaches:

1. **Transformer from Scratch:** Implemented and trained an encoder-decoder Transformer using PyTorch.
2. **Transfer Learning:** Switched to the pretrained Qwen2.5-1.5B-Instruct language model to leverage its existing language understanding and conversational capabilities.
3. **LoRA Fine-Tuning:** Adapted Qwen2.5 to conversational data from DailyDialog using Low-Rank Adaptation.
4. **Evaluation and Deployment:** Compared responses before and after fine-tuning and built a Gradio interface for interactive conversations.

This progression demonstrates an iterative machine learning workflow: implement, evaluate, identify limitations, and improve the approach.

## Development Journey

### 1. Building a Transformer from Scratch

I initially attempted to build the conversational model from the ground up using PyTorch, implementing an encoder-decoder Transformer architecture.

The model was trained on DailyDialog, a dataset containing everyday conversations.

**Architecture and configuration:**

- Framework: PyTorch
- Architecture: Encoder-decoder Transformer
- Encoder layers: 3
- Decoder layers: 3
- Model dimension (`d_model`): 256
- Attention heads: 8
- Feed-forward dimension: 1,024
- Dropout: 0.1
- Vocabulary size: 17,710
- Total parameters: Approximately 14.6 million

**Initial results:**

- Best recorded validation loss: 3.3732
- Token-level accuracy reached approximately 39.27% during training.

Although the model learned conversational patterns, its generated responses were sometimes irrelevant, unnatural, or poorly connected to the input.

This highlighted an important lesson: implementing a Transformer architecture is only one part of building a capable chatbot. Data representation, training scale, optimization, and language modeling quality also play critical roles.

### 2. Moving to Transfer Learning with Qwen2.5

The limitations of the scratch implementation motivated me to explore transfer learning instead of continuing to train a relatively small model from random initialization.

I selected **Qwen2.5-1.5B-Instruct**, a pretrained instruction-tuned causal language model.

Using a pretrained model provided a stronger starting point because it already possessed general language modeling and instruction-following capabilities.

**Configuration:**

- Base model: `Qwen/Qwen2.5-1.5B-Instruct`
- Model size: Approximately 1.5 billion parameters
- Quantization: 4-bit NF4
- Quantization support: BitsAndBytes
- Inference framework: Hugging Face Transformers
- Device: CUDA GPU

The model was loaded locally in the Colab runtime without requiring a paid inference API. The pretrained weights were obtained from Hugging Face.

Initial tests showed substantially more coherent and relevant responses than those produced by my from-scratch Transformer.

### 3. Dataset Preparation: DailyDialog

I used DailyDialog to adapt the pretrained model to everyday conversational exchanges.

The dataset was divided into training, validation, and test sets.

| Split | Original Dialogues | Generated Training Pairs |
|---|---:|---:|
| Training | 11,118 | 76,052 |
| Validation | 1,000 | 7,069 |
| Test | 1,000 | 6,740 |

Each dialogue was converted into context-response examples. Up to the three preceding utterances were used as context, with the next utterance serving as the target response.

For the initial fine-tuning experiment, I selected a subset of the data:

- Training examples: 12,000
- Validation examples: 1,500
- Training epochs: 1

The training objective was designed to calculate the language modeling loss on the assistant's response rather than the system prompt or user message.

### 4. Parameter-Efficient Fine-Tuning with LoRA

Instead of updating all the parameters of the pretrained language model, I used **Low-Rank Adaptation (LoRA)** to introduce trainable low-rank updates to selected model layers.

This approach reduces the number of trainable parameters and makes experimentation with large pretrained models more practical on limited GPU resources.

**Training configuration:**

| Parameter | Value |
|---|---|
| Base model | Qwen2.5-1.5B-Instruct |
| Fine-tuning method | LoRA |
| Quantization | 4-bit NF4 |
| LoRA rank (`r`) | 8 |
| LoRA alpha | 16 |
| LoRA dropout | 0.05 |
| Learning rate | 0.0002 |
| Per-device batch size | 2 |
| Gradient accumulation steps | 8 |
| Epochs | 1 |
| Training examples | 12,000 |
| Validation examples | 1,500 |

The LoRA configuration targeted attention and feed-forward projection layers, including `q_proj`, `k_proj`, `v_proj`, `o_proj`, `gate_proj`, `up_proj`, and `down_proj`.

**Final recorded training metrics:**

| Metric | Value |
|---|---:|
| Training loss | 2.237820 |
| Validation loss | 2.072863 |
| Training duration | Approximately 2 hours and 9 minutes |

The adapter was saved separately from the pretrained base model, allowing the fine-tuned version to be reloaded without repeating the training process.

### 5. Evaluation: Before vs. After Fine-Tuning

To investigate whether fine-tuning improved the chatbot, I evaluated the base model and the LoRA-adapted model on the same set of 14 prompts covering conversational and informational tasks in English and Arabic.

The evaluation included:

- Greetings and casual conversation
- Emotional support and everyday situations
- Confidence and concentration advice
- Introductory machine learning concepts
- Programming guidance
- Relationships and communication
- General knowledge
- Arabic conversation and AI explanations

**Observed results:**

The generated responses in the initial before-and-after comparison were identical across the 14 prompts.

This means that the current evaluation did not demonstrate an observable improvement in generated responses after fine-tuning. The Arabic tests also exposed limitations in language consistency and response quality.

These findings are important because a lower validation loss does not automatically guarantee better conversational behavior.

Further investigation would be needed to determine how much the adapter changes the model's output distribution, whether broader multi-turn evaluation reveals improvements, and whether additional fine-tuning or dataset adjustments would be beneficial.

Rather than claiming an improvement that the experiment did not establish, this project documents the result as part of the model evaluation process.

## Running the Project

### 1. Install dependencies

```bash
pip install torch transformers peft accelerate bitsandbytes gradio pandas
```

### 2. Load the pretrained model

```python
from transformers import (
    AutoTokenizer,
    AutoModelForCausalLM,
    BitsAndBytesConfig
)
from peft import PeftModel
import torch

BASE_MODEL_ID = "Qwen/Qwen2.5-1.5B-Instruct"
ADAPTER_PATH = "/path/to/qwen_daily_dialog_lora"

compute_dtype = (
    torch.bfloat16
    if torch.cuda.is_bf16_supported()
    else torch.float16
)

quantization_config = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_quant_type="nf4",
    bnb_4bit_compute_dtype=compute_dtype,
    bnb_4bit_use_double_quant=True
)

tokenizer = AutoTokenizer.from_pretrained(BASE_MODEL_ID)

base_model = AutoModelForCausalLM.from_pretrained(
    BASE_MODEL_ID,
    quantization_config=quantization_config,
    device_map="auto"
)

model = PeftModel.from_pretrained(
    base_model,
    ADAPTER_PATH
)

model.eval()
```

Replace `/path/to/qwen_daily_dialog_lora` with the actual adapter directory.

### 3. Launch the Gradio interface

After loading the model and defining a chat-generation function that applies the Qwen chat template, the model can be connected to a Gradio `ChatInterface` for interactive conversations.

The full startup workflow can be run in Google Colab, with the adapter stored on Google Drive to avoid repeating fine-tuning after a runtime restart.

## Key Lessons Learned

- Building a Transformer from scratch provides valuable insight into architecture, tokenization, training, and optimization, but does not guarantee competitive conversational performance.
- Transfer learning provides a strong starting point by leveraging pretrained language representations.
- LoRA offers a practical way to adapt large language models without full-model fine-tuning.
- Quantization helps reduce GPU memory requirements, making experimentation more accessible.
- Validation loss and conversational quality measure different aspects of model behavior.
- Fair before-and-after comparisons are essential for determining whether fine-tuning provides meaningful benefits.
- Arabic and multilingual response quality require explicit testing rather than assumptions based on English performance.
- A reproducible workflow should preserve model checkpoints, adapters, evaluation prompts, and generated outputs.

## Future Improvements

- Expand the evaluation set and include multi-turn conversations.
- Investigate why the initial before-and-after generations were identical.
- Evaluate adapter effects using token-level logits and additional decoding settings.
- Experiment with more training examples and multiple epochs where justified by validation results.
- Improve Arabic and Egyptian Arabic conversational behavior.
- Add automated evaluation metrics alongside human assessment.
- Build a persistent deployment workflow beyond temporary Colab sessions.
- Compare the scratch Transformer, pretrained Qwen, and fine-tuned Qwen under consistent evaluation conditions.

## Conclusion

This project represents a practical exploration of conversational AI development, from implementing a Transformer from scratch to adapting a pretrained language model using transfer learning and LoRA.

The main outcome is not simply a trained chatbot, but an end-to-end experimentation workflow that includes dataset preparation, model training, adapter persistence, comparative evaluation, and a conversational interface.

The initial results also demonstrate an important principle in machine learning: **a successful training run is not the same as a demonstrated improvement in model quality.** Careful evaluation is necessary to determine whether a modeling change actually achieves its intended goal.
